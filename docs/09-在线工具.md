# 09 · 打卡与在线看板（GitHub Pages）

> 这一页解决三个问题：**在哪里打卡、数据存哪里、手机上怎么用**。
> 看板本身是一个纯静态 HTML，部署在 GitHub Pages 上也能用；区别只在「数据是否跨设备同步」。

---

看板能力：

- 每日打卡：日期、小时、专注内容、产出链接、一句收获。

- 数据默认存在浏览器 `localStorage`（键 `atlas-tracker-v1`）。

## 2. 数据存哪里：三种模式

| 模式 | 数据位置 | 跨设备 | 安全性 | 适合 |
|---|---|---|---|---|
| A. 浏览器本地 | 手机/电脑各自 localStorage | ❌ | 高（不上传） | 先跑起来、单设备 |
| B. GitHub Actions 打卡 | 仓库 `data/checkins.json` | ✅ | 高（不用 PAT） | 日常主力推荐 |
| C. 导出 JSON 手动提交 | 仓库 `data/checkins.json` | ✅ | 高 | 批量补录、备份 |

> 看板会**自动尝试读取** `../data/checkins.json`：如果本地没有数据，就直接用云端备份；如果本地有数据，会按日期/更新时间合并。打开看板时如果看到「云端已合并：新增 N 条」，说明生效了。

---

## 3. 模式 B：用 GitHub Actions 打卡（推荐）

### 3.1 一次性配置

1. 把仓库推到 GitHub（public 仓库才能免费用 Pages；私有仓库需要 GitHub Pro）。
2. 仓库 **Settings → Actions → General → Workflow permissions** 选 **Read and write permissions**（否则 workflow 不能提交 `data/checkins.json`）。
3. **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
4. 推送 `main` 分支，等待 `Deploy GitHub Pages` 工作流完成。

### 3.2 每天打卡

1. 打开仓库的 **Actions** 标签页。
2. 左侧选 **每日打卡（Cloud Check-in）**。
3. 点 **Run workflow**，填：
   - `date`：留空 = 今天（Asia/Shanghai）；补录填 `2026-11-12`。
   - `hours`：今天投入小时数，如 `2`。
   - `focus`：今天做了什么（一句话）。
   - `link`：commit / 博客 / 文档链接（可空）。
   - `takeaway`：一句收获（可空）。
4. 运行完成后，workflow 会提交 `data/checkins.json`，Pages 自动重新部署；打开看板即可看到。

> 手机 GitHub App 也能操作：仓库 → Actions → 选择 workflow → Run workflow。
> 如果 Actions 页面没有这个 workflow，确认 `.github/workflows/checkin.yml` 已推送，且默认分支是 `main`。

### 3.3 手动合并已导出的 JSON

在看板点「导出 JSON 备份」，然后在本地执行：

```bash
python3 scripts/cloud_checkin.py --from-json ~/Downloads/atlas-tracker-2026-11-12.json
git add data/checkins.json
git commit -m "checkin: 2026-11-12"
git push
```

`--from-json` 会读取看板导出的 `data.records` / `data.checks`，合并进 `data/checkins.json`，不会覆盖其他日期。

## 4. 模式 A：只用浏览器本地（最简单）

- 打开看板 → 填今天的小时/内容 → 保存。
- 换设备/清缓存前点「导出 JSON 备份」。
- 新设备打开看板 → 「导入 JSON」→ 选择备份文件。
- 优点：零配置、数据不上传；缺点：不跨设备、不自动备份。

## 5. 常见问题

**Q1：GitHub Pages 打开是 404 / CSS 没加载？**
A：项目站点必须用 `/<仓库名>/` 作为 base。仓库里的部署工作流会自动计算；如果你绑定了自定义域名，在仓库 **Settings → Variables → Actions** 新建 `BASE_PATH`，值设为 `/`，再重跑部署。

**Q2：看板数据会丢吗？**
A：localStorage 可能被浏览器清理；请每周导出一次 JSON，或用模式 B/C 提交到仓库。仓库里的 `data/checkins.json` 是长期备份。

**Q3：仓库是 public，打卡记录会公开吗？**
A：会。记录只有学习时长/内容/链接，不要写公司机密、密钥、个人隐私。介意的话用模式 A，或把仓库设为 private（Pages 需 GitHub Pro）。

**Q4：能不能不手动跑 Actions，自动每天打卡？**
A：不能「自动知道你今天学了什么」；但可以设置每天 22:00 的提醒 issue（GitHub Actions schedule + issues:write），到点提醒你去打卡。提醒不等于自动填写。

**Q5：能不能多设备实时同步、多人协作？**
A：GitHub Pages 是纯静态托管，没有服务端。实时同步需要外部后端（Supabase / Cloudflare Worker + D1 / Firebase）。当前方案是「提交式同步」，延迟 = Actions 运行时间（约 20–60 秒），对个人学习足够。

**Q6：Actions 打卡会不会消耗很多额度？**
A：public 仓库的 Actions 一般免费；每次打卡只跑几十秒。私有仓库按账号额度计。

## 6. 文件与命令

| 文件 | 作用 |
|---|---|
| `tracker/index.html` | 离线看板（构建后复制到 `public/tracker/index.html`） |
| `data/checkins.json` | 云端打卡数据（Actions / 手动提交） |
| `scripts/cloud_checkin.py` | 合并打卡数据（CLI） |
| `.github/workflows/checkin.yml` | GitHub Actions 打卡表单 |
| `.github/workflows/deploy-pages.yml` | 构建并部署 Pages |
| `scripts/prepare_site.py` | 构建前复制 tracker / plan / data 到 `public/` |

```bash
# 本地补录一条
python3 scripts/cloud_checkin.py --date 2026-11-12 --hours 2 \
  --focus "Spring AI streaming + SSE" --takeaway "Flux 到 SSE 的封装"

# 从看板导出文件合并
python3 scripts/cloud_checkin.py --from-json ./atlas-tracker-2026-11-12.json

# 校验数据
python3 scripts/validate_plan.py
```
