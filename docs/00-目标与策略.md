# 00 · 目标、定位与策略

> 这份文档回答三个问题：**你要去哪儿（20K 的 AI 应用/Agent 岗）**、**你凭什么去（差异化定位）**、**22 周怎么分配（时间与取舍）**。
> 路线图负责「做什么」，本文件负责「为什么这么做」。所有取舍都可以被面试官追问，所以必须能讲清。

---

## 1. 一句话结论

> **用 22 周，把「Java 企业级工程能力」翻译成「AI 应用/Agent 的落地能力」，用一个可演示、有数字、有取舍的全栈项目作为证据，在 2027 年金三银四拿到 20K 档 offer。**

不是去和算法工程师拼论文、拼训练、拼 GPU；也不是丢掉 Java 去当 Python 新人；更不是花三个月把前端学到能过专职前端面试。

你的战场是：**企业存量系统里，把大模型能力安全、稳定、算得清成本地接进去。**

## 2. 目标拆解：offer 是一个乘法

```
offer = 能力证据 × 岗位匹配 × 面试表达 × 时间窗口
```

| 因子 | 你要做到 | 对应动作 |
|---|---|---|
| 能力证据 | 1 个旗舰项目 + 2 个特色小作品 + 评估数字 | 项目主线，见 `04-旗舰项目Atlas.md` |
| 岗位匹配 | Java + AI + 全栈，命中「AI 应用/Agent/AI 平台」类 JD | 选岗与简历，见 `05-面试与求职作战.md` |
| 面试表达 | 能讲清「为什么」、能扛 5 层追问、能手写核心机制 | 每周输出 + 回炉日 + 模拟面试 |
| 时间窗口 | 2027 年 3 月主投，4 月中前拿 offer | 22 周排期，W16 开始试水投递 |

任何一项为 0，结果都是 0。**最容易被忽略的是「时间窗口」**：很多技术不错的人拖到 5 月才投，岗位坑位已经少了。

## 3. 20K 到底意味着什么

### 3.1 先校准预期

> 以下为方向性判断，具体区间请以你所在城市、当前薪资、面试表现为准；`research/2026-市场与技术调研.md` 里有带来源的样本。

| 城市/类型 | 20K 大致对应 | 说明 |
|---|---|---|
| 北京/上海/深圳/杭州（AI 应用/Agent 岗） | **3–5 年段的中低位**，不是高位 | 样本里 3–5 年常见 15–25K、20–30K·17 薪；20K 是「能独立交付一个模块」的价，25–35K 才要求「带过上线的 Agent」 |
| 成都/南京/武汉/西安 | 3–5 年段的中高位 | 往往要求能独立从 0 到 1，或带小团队 |
| 传统 Java 后端（同经验） | 15–22K | 纯 CRUD 背景直接跳 AI 岗，20K 有难度，需要项目证据 |
| 20K 主力雇主 | 外包 / 中型软件 / 传统行业数字化 | 大厂 AI 应用岗起点常 25–40K，但要求更高；先把 20K 作为「上岸线」，不是终点 |

> **重要校准（2026-11 调研）**：20K 在 2026 年的 AI 应用/Agent 市场里是「**3–5 年段下四分位附近**」，不是高薪。这意味着两件事：
> ① 20K 可达，但需要「上线证据 + 评测证据 + 全栈 demo」三件套，光有项目 demo 会被压到 15–18K；
> ② 谈判时可以**开 22–25K**，给自己留空间；如果岗位预算只有 20K，优先看成长与上线机会，1–2 年后再跳。
> 具体样本与来源见 `research/2026-市场与技术调研.md` §1.2–1.3。

**20K 不是「会调 API」，而是「能对结果负责」**：功能上线、指标达标、出问题能定位、成本算得清、跨端能交付。

### 3.2 招聘方在 20K 档真正买的 5 样东西

1. **能落地**：不是 demo，是能处理脏数据、权限、异常、并发、部署的系统。
2. **能评估**：说得出 recall@5、faithfulness、任务成功率、P95、单次成本，并且有对比实验。
3. **能排障**：RAG 答错时，能定位是解析、切分、检索、rerank、prompt 还是模型的问题。
4. **能算账**：token 成本、缓存命中、模型路由、降级策略，能给出降本数字。
5. **能协作**：前端能自己接、接口能自己定、文档能自己写、跨团队能推动。
6. **能用 AI 工具**：Claude Code / Codex / Cursor 不是「玩具」，2026 年已有 JD 把「重度使用经验」写进硬要求；你要能讲清「怎么用 coding agent 在 2 周内交付一个全栈 demo」。

### 3.3 你的五个证据（面试前必须凑齐）

| 证据 | 形式 | 及格线 |

| 评估报告 | Markdown/Notion | 至少 3 个指标，有基线 vs 优化后 |

| 全栈交付 | 项目里的前端 + 后端 | 能独立改 UI、接 SSE、做审批流 |
| 表达能力 | 博客/分享/模拟面试 | 每周 1 篇，能扛追问 |
| AI 编程工具 | commit 历史 / CLAUDE.md / 效率复盘 | 能讲清「用 Claude Code 做了什么、省了多少时间、怎么 review」 |

## 4. 你的资产与负债

### 4.1 资产：不是「只会 Java」，是「会企业级工程」

| Java 后端能力 | 翻译成 AI 应用语言 | 面试里的价值 |

| Spring / 依赖注入 / AOP | Spring AI Advisor、拦截器、统一鉴权 | 能讲清框架扩展点 |
| 高并发 / 线程池 / 异步 | 流式 SSE、虚拟线程、背压、超时 | AI 应用普遍慢，并发是真痛点 |
| MySQL / Redis / ES | pgvector、语义缓存、混合检索 | 检索与成本优化的基础设施 |
| MQ / 定时任务 | 异步 ingestion、评测任务、批处理 | 长任务与解耦 |

| 监控 / 日志 / 压测 | Trace、Token 成本、P95、错误率 | 多数 AI 候选人空白 |
| 微服务 / 网关 | 模型网关、路由、降级、灰度 | 20K 档的加分项 |

### 4.2 负债：必须补，但不必补成专家

| 短板 | 补到什么程度 | 怎么补 |
|---|---|---|
| Python | 能读、能改、能写脚本和 FastAPI 小服务 | 第 1–2 周集中补，之后每周 2–3h |
| LLM 概念 | 能讲清 token、上下文、采样、Embedding、幻觉 | 边做边学，卡片 + 复述 |

| 表达 | 能 3 分钟讲项目、扛 5 层追问 | 每周博客 + 回炉日模拟面试 |

## 5. 差异化定位

### 5.1 一句话定位

> **「我是能把大模型能力做成企业级、可运维、算得清成本、并有完整前端产品的工程师，不是只会调 API 的人。」**

三个关键词，面试全程反复出现：

1. **工程化**：权限、租户、审计、限流、降级、灰度、部署。
2. **可观测 + 成本**：trace、指标、token 账本、缓存、模型路由。
3. **全栈交付**：后端 + 前端 + 评测 + 文档，一个人能闭环。

### 5.2 30 秒自我介绍模板

> 我有 N 年 Java 后端经验，做过 XX（高并发/微服务/权限/稳定性）。过去 5 个月我把这套工程能力迁移到大模型应用：独立完成了一个企业知识库 + Agent 工作台，覆盖文档解析、混合检索、状态图编排、MCP 工具、人工审批、评测与成本治理。检索 recall@5 从 X 提到 Y，答案忠实度 Z，P95 首 token X ms，单次会话成本从 X 降到 Y。我的定位不是算法研究，而是**让 AI 能力在企业系统里稳定、可控、算得清地跑起来**。

数字在项目完成后替换成真实值；没有数字就先别吹，用「正在测」也比编好。

### 5.3 你与三类竞争者的对比

| 竞争者 | 他们的优势 | 你的打法 |

| Python 算法/应用候选人 | Python 熟、框架熟、模型理解深 | 你比他们懂企业工程、并发、权限、成本、Java 存量系统 |

## 8. 技术栈选型（为什么是这套）

### 8.1 总原则

- **主线用 JVM**：你的存量优势、企业客户存量系统、JD 里 Spring AI / LangChain4j 的真实需求，都是别人抢不走的差异化。
- **Spring AI 2.0.x 做主线框架**（2026-06 GA，2.0.2 为维护版）；Spring AI 2.1 的 Session Memory / 工具确认 / Message Parts 作为加分项了解，不在 RC 上做正片项目。
- **Spring AI Alibaba 只作加分项**：截至 2026-11 可查最新为 1.1.2.0（对齐 Spring AI 1.1.2），未核实到对齐 2.x 的版本；**不要和 Spring AI 2.x 混用**，作品集二选一。目标 JD 明确点名 SAA 时再投入。
- **LangGraph4j / LangChain4j 作为对照与备选**：LangChain4j 1.23 的 AI Services / 决策模型 / Judge 值得读；LangGraph4j 1.8.8 用来学「图编排 + 状态 + checkpoint」，和 Python LangGraph 对照。
- **副线用 Python**：RAG/Agent 生态、评测工具、LangGraph 对照实验、部分面试要求。够读够改够写脚本，不追求精通。
- **前端一条线**：TypeScript + React + Next.js（16.x）+ Vercel AI SDK 6，组件库优先，目标是「能交付 AI 产品界面」。
- **MCP 按 2026-07-28 新规范学**：已无状态化（去 session、去 initialize、`server/discover`、MRTR），2025 年教程大量过时；以 `modelcontextprotocol.io` 当前 changelog 为准。
- **一个模型网关**：所有模型调用走统一封装，方便横评、降级、算成本。

### 8.2 技术栈全景

| 层 | 主线（JVM） | 副线（Python） | 前端 |
|---|---|---|---|
| 语言 | Java 21/25 | Python 3.12 | TypeScript |
| 框架 | Spring Boot 3.5+/4.x、Spring AI 2.0.x；对照 LangChain4j 1.23 / LangGraph4j 1.8.8 | FastAPI、LangGraph 1.2.x、OpenAI SDK | Next.js 16.x（App Router）、React 19 |
| LLM 接入 | Spring AI ChatClient / Advisor / Tool Calling | openai / httpx | Vercel AI SDK 6 |
| 检索 | pgvector 0.8.x、Elasticsearch kNN | LlamaIndex（选学） | — |
| 状态/缓存 | Redis | Redis | — |
| 工具协议 | MCP Java SDK（2026-07-28 规范，需实测框架支持） | MCP Python SDK | — |
| 评估 | 自建 Java 评测 runner + langchain4j-test Judge（可选） | RAGAS / DeepEval / promptfoo | 评估看板 |
| 可观测 | OpenTelemetry + Langfuse | Langfuse SDK | 看板 |
| 部署 | Docker Compose、基础 K8s | Docker | Vercel / Docker |
| 压测 | k6 / JMeter | — | — |
| AI 编程 | Claude Code / Codex（CLAUDE.md、MCP、Skill） | Cursor / Aider（辅助） | v0 / shadcn/ui |

> 版本号以官方当前稳定版为准；不要为了追新版本重写项目。选型的判据、备选、代价和「什么情况下改选」记进 `DECISIONS.md`。

### 8.3 关键选型说明

| 决策 | 选择 | 理由 | 什么情况下改选 |
|---|---|---|---|
| 主语言 | Java | 存量优势 + 企业 AI 落地岗 + JD 点名 Spring AI 生态 | 目标岗位明确要求 Python 为主，且 Java AI 岗样本不足时，提高 Python 占比 |
| 主线框架 | Spring AI 2.0.x | 2026-06 GA、生态稳、企业采用广；2.1 的 Session Memory/工具确认可加分 | 团队已统一 LangChain4j，或需要更轻的 AI Services 时 |
| 编排 | LangGraph4j（或 ADK for Java 1.0） | JVM 侧能落地、能讲状态图与 checkpoint；与 Python LangGraph 对照 | 团队已统一 LangGraph，或 JVM 侧客户端缺失严重时，Python 为主 |
| Spring AI Alibaba | 只用 1.1.2.0 做加分项 | JD 点名时有用；中文生态/Graph/Skills 有亮点 | 未核实到对齐 Spring AI 2.x；**不与 Spring AI 2.x 混用** |
| 向量库 | PostgreSQL + pgvector | 与现有 DB 运维能力一致，支持 JOIN 做权限过滤，部署简单 | 数据量 > 千万或需要 GPU 加速时换 Milvus/Qdrant |
| 前端 | Next.js 16 + React 19 + AI SDK 6 | 一条主线、流式/工具 UI 生态成熟 | 只做内部工具时 Vite + React 足够 |
| 模型 | 一主一备（国产 + 海外） | 成本、合规、可用性；国产模型价格优势明显 | 客户指定私有化时换本地模型 |

### 8.4 明确不学的（省 100+ 小时）

见 §4.3。再强调一次：**不要同时学三个 Agent 框架，不要把 LangChain 所有组件学一遍，不要为了「全栈」去学 Vue/Angular。**
