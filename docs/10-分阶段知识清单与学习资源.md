## 1. 怎么用这份清单

### 1.1 三个标记

| 标记 | 含义 | 你要做到 |
|---|---|---|
| **必须写** | 面试和项目都直接用 | 不看资料能写出来、能改、能排障 |
| **必须讲** | 面试高频，项目要讲取舍 | 能 2 分钟讲清：是什么、为什么、代价、替代 |
| **加分** | 20K 档的差异化 | 能说清概念 + 一个有数字的例子 |
| **知道** | 知道边界即可 | 被问到时能说「它解决什么、我为什么没选」 |

> 不要把所有「知道」学到「能写」。22 周的时间只够把 B/C/D 三块学到 4 分，其他到 3 分就停。

### 1.2 每个知识点的验收三问

1. **能讲**：合上资料，2 分钟讲清它是什么、解决什么问题、代价是什么。
2. **能写**：不看示例，写一个最小可运行版本（或改一处并验证）。
3. **能排障**：给它一个失败场景，你能说出 3 个可能原因和定位顺序。

三问过不了，就不算学会；继续看视频/读文档没用。

### 1.3 时间与资源纪律

- **动手 ≥ 40%，文档 ≤ 30%，视频 ≤ 30%**。视频只看一套，1.25–1.5 倍速，边看边敲。
- 每看完一节/一集，写 3 行笔记 + 1 张卡片；否则等于没看。
- 官方文档优先；视频用于「建立直觉/看演示」，不用于「替代文档」。
- 中文视频更新快、质量参差：先看发布时间和版本，链接失效就用文末搜索关键词。
- 同一主题最多一门课；没跑完代码，不开下一门。

### 3.2 学习顺序（3 周）

- **W3**：Prompt 四要素 → few-shot/CoT → 上下文/截断 → 注入攻防 → judge → eval harness。
- **W4**：工具 schema → 手写 tool loop → ReAct → 工具失败处理 → 前端对话体验 → 第一次模拟面试。
- **W5**：Atlas 立项 → 100 条评测集 → 解析原型 → 架构/ADR → JD 词频。

### 3.3 必做实验

- Prompt 矩阵：同一任务 4 种写法 × 5 次，记录质量/长度/稳定性。

- 手写 tool loop：不用框架，解析 tool_calls → 执行 → 回传 → 循环。
- ReAct：白板重写 + 与框架对照。
- 注入红队：20 条（直接/间接/工具返回/越权），记录拦截率。
- eval harness：数据集格式、跑批、指标、报告。

### 3.5 常见坑

- 把 Prompt 当玄学 → 每次改动必须有基线对比。
- 只做「能跑」的 Agent → 没有失败处理，面试一问就穿。
- 评测集全是简单题 → 至少 30% 多跳/拒答/边界。
- 安全只加一句 system prompt → 必须有输入过滤、工具权限、输出校验。

### 4.5 常见坑
