# 07 · 这份文档是怎么生成的

> 你问「你如何生成这个文档」。这一份把过程、依据、取舍、工具和可复用的提示词全部摊开。
> 目的有两个：让你知道**哪些结论可信、哪些需要你自己核实**；以及让你以后能**自己用 AI 生成/调整**同类计划，而不是依赖某一次回答。

---

## 1. 总体方法：从目标反推，而不是从知识目录正推

大多数人做学习计划是「把 AI 知识列一遍，排进 24 周」——这叫**课程目录式计划**，看起来全，执行起来散。

我用的是**目标反推**：

```
offer 日期 → 面试流程 → 岗位要求 → 能力证据 → 项目 → 周任务 → 每日动作
```

具体 10 步：

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 | 提取约束 | 目标、时间、基础、城市、薪资、每周小时 |
| 2 | 拆解 offer 公式 | 能力证据 × 岗位匹配 × 面试表达 × 时间窗口 |
| 3 | 读旧资料，提取原则 | 哪些可复用、哪些要改、哪些是坑 |
| 4 | 市场调研 | JD 高频要求、技术栈、薪资、面试考察 |
| 5 | 建能力模型 | 6 维权重 + 评分标准 + 目标分 |
| 6 | 时间预算 | 22 周 × 20h ≈ 456h，按阶段分配 |
| 7 | 设计项目主线 | 一个项目三次演进，评测先行 |
| 8 | 设计习惯系统 | 日/周/月循环 + 防断更 + 指标 |
| 9 | 设验收与降级 | 里程碑、硬标准、砍范围顺序 |
| 10 | 多角色评审 + 固化 | 文档、工具、模板、维护规则 |

## 2. 约束提取：这份计划只适用于「你」

| 约束 | 取值 | 对计划的影响 |
|---|---|---|
| 起点 | Java 后端 3+ 年，Spring/MySQL/Redis/MQ | 主线用 JVM，不丢存量优势 |
| AI/前端基础 | 接近零（但有学习意愿） | 前 2 周补地基，前端只到「够用线」 |
| 时间 | 2026-11-05 起，目标 2027 年 4 月 | 22 周（11/09–04/11），不是 6 个月 |
| 投入 | 在职，每周约 20h | 标准档；不排「全天学习」的计划 |
| 目标 | AI 应用/Agent 开发，全栈，20K | 项目要覆盖 RAG + Agent + 前端 + 工程化 |
| 城市/薪资 | 20K 档（一线为主） | 能力标准按「独立负责模块」定，不按「入门」定 |
| 输出 | 需要能通过面试 | 每周输出 + 模拟面试 + 投递排期 |

**关键假设**（如果不成立，计划要改）：

- 你每周真能投入 18–22h；如果只有 10h，切保守档，周期延到 6 月。
- 你能拿到可用的真实文档/业务场景做项目；拿不到就用公开文档替代，并在面试中说明。
- 你所在城市有 AI 应用/Agent 岗位；如果很少，扩大范围（Java+AI、AI 平台、远程）。
- 20K 是「一线城市 3–5 年」的档位；二线要按当地购买力折算。

## 3. 目标反推：为什么是 22 周、这些阶段

### 3.1 从 offer 日期倒推

```
2027-04-11  目标 offer
   ↑ 4 周   终面/谈判/决策（W19–W22）
   ↑ 4 周   一面/二面/复盘（W15–W18，金三银四）
   ↑ 2 周   简历/作品集/试水（W15–W16）
   ↑ 9 周   项目 v2/v3（W8–W16）
   ↑ 4 周   项目 v1（W4–W7）
   ↑ 3 周   基本功（W1–W3）
```

**结论**：技术准备到 2 月底，3 月主投，4 月中拿 offer。任何「5 月再投」的计划都错过金三银四。

### 3.2 为什么不是 24 周 / 34 周

- 旧版 A 是 24 周（10/26 起），但今天已经 11/05，按 24 周会到 4 月中才学完，没时间面试。
- 旧版 B 是 34 周（到 6 月），目标是 4–6 月，但你的目标是 4 月，34 周会稀释强度。
- **22 周是「4 月拿 offer」的硬约束**；内容按 22 周重新裁剪，而不是把 24 周计划压缩。

### 3.3 为什么前 5 周是「基本功 + 立项」

- W1–W2：不会调模型、不会写 tool loop，后面 RAG/Agent 都是空中楼阁。
- W3：上下文与安全，是后面所有模块的地基。
- W4：手写 ReAct + 第一次模拟面试，尽早暴露表达问题。
- W5：立项 + 评测集，避免「先写代码后想评估」。

### 3.4 为什么 RAG 在 Agent 之前

- RAG 训练：解析、切分、检索、评估、权限——这些是 Agent 的上下文来源。
- Agent 需要：工具、状态、记忆、失败恢复——比 RAG 更复杂。
- 面试追问顺序也通常是：RAG 基础 → Agent 进阶 → 工程化。

### 4.2 哪些结论是「已核实」，哪些是「推测」

| 类型 | 例子 | 可信度 |
|---|---|---|
| 已核实 | Spring AI 2.0.2 / MCP 2026-07-28 / LangChain4j 1.23 等版本与能力；JD 高频词；12 条 JD 样本 | 高（官方/样本） |
| 方向性 | 20K 是 3–5 年段**中低位**（15–25K 常见），主力雇主是外包/中型软件/传统行业数字化 | 中（样本约 40 条，猎头发布为主） |
| 推测 | 2027 年金三银四岗位量、竞争强度 | 低（无法准确预测） |
| 你的情况 | 你当前能力分、每周实际投入 | 需要你自己校准 |

**薪资与岗位数据不要当承诺**；它们是用来定「能力标准」和「谈判区间」的，不是保证。**20K 不是高薪，是上岸线**；25–35K 才要求「带过上线的 Agent / 平台」。

### 4.3 为什么选 JVM 主线（而不是 Python 主线）

旧版 A 选 Python 主线，理由是「90% AI 岗以 Python 为主」；旧版 B 选 JVM 主线，理由是「Java 存量优势 + JD 点名 Spring AI Alibaba」。

我的判断：

1. 你的**差异化**在 Java 企业级工程，不在 Python 熟练度；短时间补 Python 到「精通」不现实。
2. 企业 AI 落地岗（金融/企业服务/大厂平台）大量存在 Java 存量系统，Spring AI 生态是真实需求。
3. Python 仍要会——评测、解析、LangGraph 对照、部分面试——但定位是**副线**，每周 2–3h，不抢主线时间。
4. 面试时你可以说：「我主线 JVM，能落地企业系统；Python 能读能改能写评测；两套编排我都做过对照。」这比「两边都半桶水」强。
5. **但不要把「JVM 主线」等同于「Spring AI Alibaba 主线」**：2026-11 可查 SAA 最新仍对齐 Spring AI 1.1.2，未核实到 2.x 版本；主线用 Spring AI 2.0.x + LangGraph4j，SAA 只作加分项/对照，避免版本混用。

**改选条件**：如果你投的 30 份 JD 里 80% 明确要求 Python 为主、且 Java AI 岗很少，就把 Python 提到 40%，JVM 降到副线。

### 4.4 为什么前端只给 15%

- JD 对 AI 应用岗的前端要求通常是「能独立做管理后台/对话页面」，不是「专职前端」。
- 你的前端目标是「交付 AI 产品界面」：流式、引用、工具时间线、审批、后台。
- 15% ≈ 65h，足够到「能用组件库独立交付」；要到「前端工程师」水平需要 300h+，不值得。
- 省下的时间投给 RAG/Agent/评测/成本——这些才是 20K 的分水岭。

## 5. 能力模型：权重怎么来的

| 维度 | 权重 | 依据 |
|---|---|---|
| RAG | 25% | JD 出现频率最高；项目最容易做出数字 |
| Agent | 25% | Agent 岗核心；区分度最高；多数候选人只会 demo |
| 工程化 | 20% | 你的优势；企业落地必需；面试深挖 |
| LLM 基础 | 15% | 必备，但纯概念题占比下降，更多结合项目 |
| 前端 | 10% | 全栈交付需要，但不是主战场 |
| 业务/表达 | 5% | 决定「能不能讲清」，权重低但影响大 |

**目标分**：B/C/D ≥ 4，A ≥ 3.5，E ≥ 3，F ≥ 3.5，加权 ≈ 3.8/5。这个分数对应「能独立负责模块 + 能讲清取舍」，是 20K 档的合理线。

## 6. 时间预算：456h 怎么算的

```
工作日 2h × 5 = 10h
周六 6h + 周日 4h = 10h
合计 20h/周 × 22 周 = 440h
加上部分周 22–26h（P4/P5），计划值 ≈ 456h
按 85% 执行率，实际 ≈ 390h
```

**分配逻辑**：

- 项目（RAG + Agent + 生产化）≈ 250h：必须占大头，否则没有作品。
- 前端 ≈ 65h：只做「项目需要」的界面，不单独学课程。
- 求职 ≈ 70h：简历、模拟、投递、谈判；不能省。
- 基础/评测/写作 ≈ 70h：贯穿在各阶段，不单独列。

**为什么不是 30h/周**：在职 + 22 周，30h/周需要每天 4h + 周末 10h，可持续性差；短期能冲，长期会崩。计划要按「最差的一周」设计，而不是「最好的一周」。

## 7. 项目设计：为什么一个项目三次演进

### 7.1 备选方案对比

| 方案 | 时间 | 深度 | 面试效果 | 结论 |
|---|---|---|---|---|
| 3 个独立项目 | 3 × 60h | 每个都浅 | 讲不深，容易被问穿 | ❌ |
| 1 个项目 3 次演进 | 1 × 180h | 深 | 有故事线、有取舍、有数字 | ✅ |
| 只做 RAG | 100h | 中 | 错过 Agent 岗 | ❌ |
| 只做 Agent | 100h | 中 | 没有检索/评测地基 | ❌ |

### 7.2 演进逻辑（面试故事线）

> RAG（查得准）→ Agent（能做事）→ Harness（做得稳、可治理）→ 生产化（扛得住、算得清）

每一阶段都解决上一阶段暴露的问题，天然形成「需求 → 方案 → 故障 → 优化」的叙事。

### 7.3 评测先行

- W5 冻结 100 条评测集，之后所有优化都跑同一套。
- 没有评测集的项目 = 玩具；这是 20K 与 15K 的分水岭。
- 指标目标（recall@5、faithfulness、任务成功率、P95、成本）是示例，按你的基线调整；**关键是「有基线、有对比、有归因」**。

### 7.4 为什么项目里要有「权限/成本/安全」

这三块是 Java 后端的优势，也是企业 AI 落地的真实痛点，还是多数转行候选人的空白。面试官一旦问到这里，你能讲 10 分钟，别人只能讲 1 分钟。

## 8. 习惯系统：为什么这样设计

| 设计 | 依据 | 效果 |
|---|---|---|
| 每天 2h 固定块 | 习惯靠触发，不靠意志 | 降低启动成本 |
| 每天 commit | 可见进度 + 外部问责 | 防止「学了一天没产出」 |
| 最低限度版 25min | 连续性 > 强度 | 防止断更崩盘 |
| 每周复盘四问 | 反馈回路 | 及时调整，不跑偏 |
| 每月回炉 | 间隔重复 + 输出 | 防止「学了就忘」 |
| 每两周模拟面试 | 提取练习 + 暴露问题 | 表达与知识同时练 |
| 公开输出 | 教学相长 + 影响力 | 面试素材 + 机会 |
| 决策日志 | 判断型知识 | 面试「为什么」的弹药 |

**核心**：把「学习」拆成**可执行的最小动作**，把「进步」变成**可见的数字**，把「坚持」变成**环境+社交+反馈**的结果。

## 10. 多角色评审：我替谁挑过刺

写完后，我用四个角色审了一遍：

| 角色 | 会挑什么 | 我怎么改 |
|---|---|---|
| 招聘经理 | 「这人能独立负责吗？有数字吗？」 | 强化项目指标、成本、权限、故障 |
| 面试官 | 「是不是背的？能扛追问吗？」 | 加 5 层追问、决策日志、手写机制 |
| 学习者（你） | 「每天到底干什么？坚持得下去吗？」 | 加周执行手册、最低限度版、打卡模板 |
| 工程师 | 「技术选型合理吗？能落地吗？」 | 加备选/判据/改选条件、降级预案 |

**没有采用的意见**：

- 「三个项目更全面」→ 22 周做不完，且讲不深。
- 「前端要 30%」→ 与岗位要求不匹配，挤占核心时间。
- 「多学几个 Agent 框架」→ 精通一个 + 对照一个足够。
- 「K8s 要深入」→ 会 Docker + 基本概念即可，面试能讲清就行。

## 11. 与旧资料的取舍（不照抄的证明）

| 决策 | 旧版 A | 旧版 B | 本版 | 理由 |
|---|---|---|---|---|
| 周期 | 24 周 | 34 周 | **22 周** | 4 月 offer 硬约束 |

| 项目 | 3 个 | 1 个三次演进 | **1 个三次演进 + 2 小作品** | 深度优先 |

**可复用的原则**（表述全部重写）：评测优先、决策日志、每周 commit、一个项目做深、求职单独排期。

## 13. 可复用的生成提示词

以后想让 AI 帮你重做/调整计划，用这个模板（把【】替换成你的情况）：

```text
你是资深 AI 应用/Agent 技术负责人 + 求职教练。请为我生成一份学习路线图与执行系统。

【我的情况】
- 背景：【Java 后端 3 年，Spring/MySQL/Redis/MQ；AI/前端接近零】
- 目标：【2027 年 4 月中前拿到 AI 应用/Agent 开发 offer，月薪 20K，一线城市】
- 时间：【2026-11-09 起，22 周；在职，每周 20h】
- 约束：【不能辞职；每周至少 1 天休息；预算有限】
- 已有资料：【旧笔记路径/项目/课程】
- 目标岗位 JD：【粘贴 3–5 份】

【要求】
```
