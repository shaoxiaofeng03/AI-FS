# 03 · 每日打卡与精进系统

> 打卡不是「证明自己很努力」，而是**让学习形成闭环**：输入 → 动手 → 反馈 → 输出 → 明天继续。
> 这份文档给你一套「日 / 周 / 月」三层循环、可直接复制的模板、防断更机制、指标看板，以及除了打卡之外更有效的精进方式。

---

## 1. 先说结论：为什么大多数打卡会死

| 死因 | 表现 | 解药 |
|---|---|---|
| 目标太大 | 「今天学完 RAG」→ 没学完 → 挫败 → 放弃 | 每天只定 1 个**可验收的最小目标** |
| 反馈太慢 | 学了两周没感觉变强 | 每天 commit、每周评测、每两周模拟面试 |
| 只有输入 | 看课/收藏/读文章，不写代码 | **动手 ≥ 60%**，没有产出的学习不算数 |
| 靠意志力 | 靠「坚持」，断一天就崩 | 降低启动成本 + 允许「最低限度版」+ 社交问责 |
| 没有记录 | 学了什么说不清 | 卡片 + 决策日志 + 周复盘 |

**一句话**：打卡系统要解决的不是「自律」，而是「**让正确的事更容易发生**」。

## 2. 系统总览：三层循环 × 三个账户

```
日循环（120min）──→ 周循环（周日 60min）──→ 月循环（回炉日 3h）
   │                    │                      │
   ├─ 输入 20'          ├─ 四问复盘            ├─ 能力体检 6 维
   ├─ 动手 60'          ├─ 指标对比            ├─ 模拟面试
   ├─ 复述 10'          ├─ 下周 3 个交付       ├─ 作品集更新
   ├─ 卡片 10'          └─ 砍范围/调计划        └─ 下月计划
   └─ commit 20'
```

**三个账户**（每周检查，别只记时长）：

| 账户 | 存什么 | 怎么看余额 |
|---|---|---|
| 时间账户 | 投入小时、深度时长 | tracker 统计 |
| 知识账户 | 卡片、笔记、决策日志、错题 | 卡片数、复习准确率 |
| 证据账户 | commit、项目、博客、demo、面试记录 | GitHub/博客/面试表 |

> 只记时间会自欺；只记知识会飘；**证据账户才是面试时能拿出来的东西**。

## 3. 每日闭环

### 3.1 标准版（工作日 120 分钟）

| 阶段 | 时长 | 做什么 | 产出 |
|---|---|---|---|
| ① 输入 | 20min | 带着 3 个问题读文档/看一节课程/读源码 | 3 个问题的答案草稿 |
| ② 动手 | 60min | 写代码/跑实验/改评测；**必须产生可运行的东西** | 代码/实验数据 |
| ③ 复述 | 10min | 合上资料，录音讲 2 个知识点，各 2 分钟；回听 | 录音/口述提纲 |
| ④ 卡片 | 10min | 把今天的易错点写成 3–5 张卡片；复习昨天 | 卡片 |
| ⑤ 提交 | 10min | commit + 更新打卡 + 写一句收获 | commit hash |
| ⑥ 明日 | 10min | 写好明天第一件事（具体到文件/函数） | 明日第一步 |

**关键纪律**：输入不超过 20 分钟。超时即停，把「读完」改成「够用」。

### 3.2 最低限度版（25 分钟，救急用）

加班/出差/生病时，不许断更，只做三件事：

1. 复习 10 张卡片（5min）
2. 做一个 15 分钟能完成的小任务（改一个 bug、写一个测试、补一段文档）（15min）
3. commit + 打卡一行（5min）

> 最低限度版的意义：**保持链条不断**。连续性是习惯的生命线，强度可以降，频率不能断。

### 3.3 周末深度版（周六 6h / 周日 4h）

- **周六上午 3h**：项目主线，关掉消息，做最难的部分。
- **周六下午 2h**：专项补强（前端/Java/评测），或补欠账。
- **周六晚 1h**：写对外文章/整理卡片。
- **周日上午 2h**：验收本周交付物 + 补漏。
- **周日下午 1h**：模拟面试或回炉。
- **周日晚上 1h**：周复盘 + 下周计划。

### 3.4 每日打卡模板（直接复制到 `checkin/`）

```markdown
# W{N} Day{M} · {MM/DD} 周{X}

**今日主题**：
**今日最小目标（只写 1 件，可验收）**：

- [ ] 输入 20min：
- [ ] 动手 60min：
- [ ] 复述 10min（录音 2 段，各 2 分钟）：
- [ ] 卡片 10min（新增 3–5 张，复习昨日）：
- [ ] commit 10min：
- [ ] 明日第一件事：

**今日产出（链接/路径）**：
**一句收获（用自己的话，带数字）**：
**卡点（具体到哪一步）**：
**自评**：专注 1–5：___ / 精力 1–5：___
**commit**：___
```

### 3.5 示例：W1 Day 1（可直接照抄格式）

```markdown
# W1 Day1 · 11/09 周一

**今日主题**：环境与 Spring AI 第一条链路
**今日最小目标**：浏览器能看到 Spring AI 的流式输出

- [x] 输入 20min：Spring AI ChatClient + streaming 文档（只读这两节）
- [x] 动手 60min：建 Spring Boot 项目，跑通 /chat/stream，SSE 返回
- [x] 复述 10min：录音讲「SSE 和 WebSocket 的区别」，回听发现漏了断线重连
- [x] 卡片 10min：新增 4 张（SSE、ChatClient、temperature、token）
- [x] commit 10min：`feat: spring ai streaming hello`
- [x] 明日第一件事：在 Next.js 里消费这个 SSE 接口

**产出**：http://localhost:8080/chat/stream
**一句收获**：Spring AI 的流式返回本质是 Flux，框架层已经处理了 SSE 封装
**卡点**：跨域配置花了 20 分钟
**自评**：专注 4 / 精力 3
**commit**：a1b2c3d
```

## 4. 每周复盘（周日 60 分钟）

### 4.1 四问

1. **完成率**：本周计划完成了百分之几？没完成的具体原因是什么（不是「忙」，要写「周三加班到 10 点」）？
2. **最大收获**：一句话，带数字或可复用资产。
3. **最卡的点**：卡在哪一步？下周用什么具体办法解决？
4. **下周三个可验收交付物**：必须是「能打开/能运行/能演示」的东西，不是「学完 XX」。

### 4.2 周复盘模板

```markdown
# W{N} 周复盘 · {MM/DD}–{MM/DD}

## 数据
- 投入小时：___ / 计划 ___
- commit 天数：___ / 7
- 卡片新增：___；复习准确率：___%
- 对外输出：___ 篇
- 模拟面试：___ 次，评分 ___
- 项目指标变化：___

## 四问
1. 完成率 ___%；未完成原因：
2. 最大收获（一句话 + 数字）：
3. 最卡的点 + 下周解法：
4. 下周三个可验收交付物：
   - ①
   - ②
   - ③

## 范围调整
- 要砍掉的：
- 要降级的：
- 要补的：

## 决策日志（≥1 条）
- 决策点 / 备选 / 判据 / 实测 / 代价 / 什么情况下改选：
```

### 4.3 周复盘的三个反模式

- ❌ 写成流水账（「周一学了 A，周二学了 B」）→ 要写判断和数字。
- ❌ 只反思不调整 → 下周计划必须变，否则复盘无效。
- ❌ 一次改太多 → 每周只改 1–2 个最关键的问题。

## 5. 每月回炉日（W4/W8/W12/W16/W20，3 小时）

| 环节 | 时长 | 动作 |
|---|---|---|
| 白板重写 | 40min | 不看资料，画出本月核心机制（agent loop / RAG 链路 / 状态图 / 网关） |
| 模拟面试 | 60min | 用 `06` 的面试官提示词，只追问不给答案，录屏 |
| 能力体检 | 20min | 6 维打分（见下表），对比上月 |
| 作品集更新 | 30min | README、指标、demo、简历 bullet |
| 下月计划 | 30min | 3 个交付物 + 1 个要补的短板 |

### 能力体检表（1–5 分）

| 维度 | 1 分 | 3 分 | 5 分 | 本月 | 上月 |
|---|---|---|---|---|---|
| LLM 基础 | 知道名词 | 能独立实现 + 评测 | 能设计选型/讲清原理 | | |
| RAG | 跑过 demo | 能独立做全链路 + 指标 | 能优化/排障/设计权限体系 | | |
| Agent | 会调工具 | 能搭状态图 + HITL + 记忆 | 能设计 Agent 平台/可靠性体系 | | |
| 工程化 | 会写接口 | 能压测/限流/缓存/可观测 | 能设计多租户/网关/成本体系 | | |
| 前端 | 会改页面 | 能独立做聊天/引用/审批 | 能设计交互/性能优化 | | |
| 表达 | 能讲概念 | 能讲项目 + 扛 3 层追问 | 能扛 5 层 + 系统设计 | | |

> 目标：B/C/D ≥ 4，A/E ≥ 3，F ≥ 3.5。低于目标就在下月计划里写具体补法。

## 6. 知识系统：让学过的东西不丢

### 6.1 四类容器

| 容器 | 放什么 | 频率 | 工具 |
|---|---|---|---|
| 笔记 | 概念、流程、源码分析 | 每天 3 行 | Markdown / Obsidian / 思源 |
| 卡片 | 「问题::答案」，可复习 | 每天 3–5 张 | Anki / 本仓库 `cards` |
| 决策日志 | 技术选择的备选/判据/数字/改选条件 | 每周 ≥1 条 | `DECISIONS.md` |
| 错题本 | 面试/评测答错、踩坑 | 每周整理 | `ERRORS.md` |

### 6.2 卡片写法

好卡片：

- `Q::RAG 里 recall@5 和 faithfulness 分别衡量什么？::recall@5 衡量检索有没有把正确文档找回来；faithfulness 衡量回答是否只依据检索到的内容，不编造。`
- `Q::为什么 Agent 场景 temperature 要低？::工具调用需要稳定复现；高温度会增加参数幻觉和格式错误。`

坏卡片：

- `Q::什么是 RAG？::检索增强生成。`（太浅，背了没用）
- `Q::Spring AI 怎么用？::看文档。`（不可判定）

**规则**：一张卡只问一个点；答案用自己的话；带数字/对比/适用条件。

### 6.3 复习节奏

- 每天 10 分钟：到期卡片 + 昨日新增。
- 每周日：本周错题卡重做一遍。
- 每月回炉：随机抽 30 张，模拟面试口述。
- 卡片不是收藏，**答不出来的卡要重写**，不是多看几遍。

### 6.4 决策日志（面试弹药库）

每条记录 6 列：日期 / 决策点 / 备选 / 判据 / 实测数据 / 代价 / 什么情况下改选。

示例：

| 日期 | 决策点 | 备选 | 判据 | 实测 | 代价 | 改选条件 |
|---|---|---|---|---|---|---|
| 12/20 | 切分策略 | 固定 512 / 递归 / 父子块 | 文档有章节结构，问题多为段落级 | 递归 recall@5 0.78 → 父子块 0.86 | 索引体积 +35% | 文档无结构或成本敏感时回退递归 |

> 面试官问「为什么这么做」时，这张表就是答案。90% 的候选人只有结论，没有判据和数字。

## 7. 输出系统：用输出倒逼输入

### 7.1 输出节奏

| 周期 | 输出 | 时长 | 目的 |
|---|---|---|---|
| 每天 | commit + 打卡 | 10min | 保持链条 |
| 每周 | 1 篇博客/笔记（500–1500 字） | 60–120min | 逼自己讲清楚 |
| 每两周 | 1 次模拟面试录音 | 60min | 暴露表达问题 |
| 每月 | 1 次分享（同事/学习群/直播） | 30min | 教是最好的学 |
| 每阶段 | 1 个 demo 视频 + 项目 README | 2h | 作品集素材 |

### 7.2 写什么（不愁选题）

- 本周踩的坑 + 怎么解决的（最有价值）。
- 一个技术选择的对比实验（带表格）。
- 读源码/读论文的笔记（用自己的话）。
- 项目指标从 X 到 Y 的复盘。
- 面试被问倒的问题 + 补完后的答案。

### 7.3 发布渠道

掘金 / 知乎 / 公众号 / B 站 / GitHub README / 公司内部分享。**先完成再完美**，500 字也算。

## 8. 反馈系统：没有反馈的练习是重复

| 反馈源 | 频率 | 怎么用 |
|---|---|---|
| 评测集 | 每周 | 指标涨没涨，badcase 是什么 |
| 模拟面试 | W4 起每 2 周 | 录音回听，找卡壳/啰嗦/答非所问 |
| 代码 review | 每周 | 找一位同行/用 AI review，重点看边界与错误处理 |
| 博客评论/阅读数据 | 每周 | 哪个点读者没看懂，就是你没讲清 |
| 面试真实反馈 | W16 起 | 记录问题，按高频缺口补 |
| 同行/学习搭子 | 每周 | 互相讲 15 分钟，互相追问 |

## 9. 防断更机制（比意志力可靠）

### 9.1 四条规则

1. **最低限度版**：再忙也做 25 分钟，保持链条。
2. **不追债超过 1 天**：昨天没做，今天补 30 分钟即可，不要「下周补一周」。
3. **每月 2 次冻结**：真有突发，允许冻结 1 天，不破坏连续记录（但要记录原因）。
4. **连续 6 周后休 1 天**：完全不想学习，休息是计划的一部分。

### 9.2 环境设计

- 电脑固定一个「学习工作区」：打开就是 IDE + 文档 + 打卡页。
- 手机放另一个房间；用 25/50 分钟计时器。
- 前一天晚上写好「明天第一件事」，降低启动阻力。
- 通勤/排队只做卡片，不刷短视频。

### 9.3 社交问责

- 找 1 个学习搭子，每周互发复盘。
- 公开承诺：朋友圈/掘金/小红书立 flag，每周更新。
- 加入 1 个 AI 学习群/开源社区，每周提 1 个问题或答 1 个问题。
- 给同事做一次 15 分钟分享，用「要讲」倒逼「要懂」。

### 9.4 奖励

- 每完成一个里程碑，给自己一个确定的奖励（一顿好的/一件装备/一天游戏）。
- 不要用「学完才能休息」惩罚自己；用「完成就奖励」正向强化。

## 11. 精进方法：让每天真的变强

### 11.1 刻意练习（Deliberate Practice）

- 只练「刚好不会」的部分：能看懂但写不出的，才是要练的。
- 每次练习有明确标准：不是「写一个 RAG」，是「recall@5 从 0.72 提到 0.85」。
- 即时反馈：跑评测、录音回听、让人追问。
- 重复弱项：连续 3 天练同一个卡点，直到能白板复现。

### 11.2 检索练习（Retrieval Practice）

- 合上资料，先自己讲/写，再看答案。
- 用「白板重写」代替「再看一遍」。
- 卡片复习不是认脸，是**先答后翻**。

### 11.3 交错练习（Interleaving）

- 不要一天只学一个主题；RAG + 前端 + 面试题交错，逼大脑建立连接。
- 每周至少 2 次跨主题练习：例如「给 RAG 做一个引用 UI」「给 Agent 加一个限流」。

### 11.4 变式练习（Variation）

- 同一知识点换场景：RAG 用在客服/法务/运维，切分和评估会怎么变？
- 同一功能换约束：成本减半、延迟减半、权限更严，方案怎么改？
- 同一问题换追问：连续问 5 层「为什么/如果」。

### 11.5 费曼技巧（Teach-back）

- 每天录音讲 2 个知识点，回听。
- 每周给同事/搭子讲 15 分钟。
- 讲不清的地方，就是没懂的地方。

### 11.6 造轮子（Build from Scratch）

至少手写一遍：tool loop、ReAct、BM25、RRF、限流器、LRU、SSE 服务端、简易分词。
**目的不是替代框架，是面试时能讲清框架替你做了什么。**

### 11.7 读源码（Source Reading）

- 从入口/自动配置进，跟一次请求链路。
- 画时序图，标出扩展点。
- 改一行代码验证理解，再还原。

### 11.8 评测驱动（Eval-driven）

- 先写评测集，再写功能。
- 每次优化必须有基线 vs 优化后。
- badcase 分类，按频次修，不按感觉修。

## 12. 除了打卡，还有哪些更有效的方式

| 方式 | 怎么做 | 为什么有效 | 适合阶段 |
|---|---|---|---|
| **在现公司落地一个小 AI 需求** | 内部知识库/工单摘要/代码助手，哪怕只有 10 个用户 | 真实数据、真实反馈、简历上写「已上线」 | 全程，最高优先级 |
| **项目驱动学习** | 先定交付物，倒推要学的知识 | 避免教程地狱，每学一点都有用 | 全程 |
| **以教代学** | 每周给同事/朋友/社区讲 15 分钟 | 讲不清 = 没懂；还能积累影响力 | W4 起 |
| **复刻 + 改进** | 选一个优秀开源项目（Dify/ LangGraph 示例 / Spring AI samples），复刻核心，加一个差异化 | 学架构，不重复造轮子 | P3–P4 |
| **开源贡献** | 文档、示例、翻译、bug fix 都算 | 面试加分、进入社区、被看见 | W15–W17 |
| **学习搭子/小组** | 2–4 人，每周互发复盘 + 互问 | 社交问责 + 不同视角 | 全程 |
| **公开构建（Build in Public）** | 每周发进度、指标、踩坑 | 建立个人品牌，可能直接带来机会 | 全程 |
| **提前面试** | W16 开始投 10 家练手 | 真实反馈比模拟更狠 | W16 起 |
| **黑客松/比赛** | 48h 做一个 AI 应用 | 逼出全栈交付与取舍 | 可选，W14 后 |
| **AI 当教练** | 出题、追问、review、模拟面试 | 低成本高频反馈，但要验证 | 全程 |
| **无 AI 手写日** | 每周 1 天不许 AI 补全，手写核心代码 | 防止「看起来会」 | W6 起 |
| **时间块 + 深度工作** | 每天 1 个 90 分钟不被打扰的块 | 高质量 > 长时间 | 全程 |
| **晨间/通勤学习** | 早上 30 分钟或通勤卡片 | 利用碎片，不占晚上 | 全程 |
| **月度分享/直播** | 每月一次公开分享 | 输出倒逼输入，积累表达 | W8 起 |
| **面试倒逼** | 把目标 JD 的问题列出来，倒推学习 | 目标明确，不跑偏 | W5 起 |

> 最有效的组合：**在现公司做一个真实小需求 + 每周公开输出 + 每两周模拟面试**。这三件事比任何课程都值钱。

## 14. 常见问题

**Q1：加班到 10 点，还要学吗？**
做最低限度版 25 分钟。不要用「今天太累」开断更的口子；也不要用「补 3 小时」报复性学习。

**Q2：周末要陪家人，时间不够？**
把学习块放在早上（家人未起/孩子午睡），或与家人约定「周六上午是我的深度时间」。22 周是马拉松，家庭支持很重要。

**Q3：学不进去/焦虑？**
先做 5 分钟最小动作（打开 IDE 改一行）；焦虑通常来自「想得太多、做得太少」。写下来：现在最卡的一件事是什么？下一步是什么？

**Q4：平台期，感觉没进步？**
正常。看滞后指标（评测/模拟面试）而不是感觉；换一种练习方式（教别人/造轮子/参加面试）；检查是不是一直在舒适区。

**Q5：计划总被打乱？**
计划本来就该被打乱。每周复盘调整，阶段目标不变，周任务可换。**保住里程碑，放过日计划。**

**Q6：要不要报课？**
可以，但一门课必须配一个项目；没跑完代码不开下一门。优先官方文档 + 免费优质资源。

**Q7：怎么判断自己真的会了？**
三层标准：① 能不看资料写出来；② 能讲清为什么/代价/替代方案；③ 能扛住 5 层追问。三条都过才算会。

**Q8：打卡断了怎么办？**
从今天重新开始，不要「补一周」。记录断更原因，调整计划（是不是目标太大/时间不对），继续。
