### P2 · RAG 生产级（W6–W9，80h）

**目标**：做出一个「有权限、有引用、有评估数字」的企业知识库 v1；这是你第一个能拿去面试的项目。

**知识清单**

| 档位 | 内容 |

| 能讲清 | chunk size/overlap 的取舍；embedding 选型；HNSW/IVF 参数；混合检索为什么有效；recall@k / MRR / nDCG；faithfulness / relevance / correctness；badcase 归因 |
| 知道 | GraphRAG、多模态 RAG、query rewrite、HyDE、语义缓存 |

**项目任务**

- `ingestion`：解析 → 清洗 → 切分 → 元数据 → 去重 → 版本/增量。
- `retrieval`：pgvector + BM25 + RRF + rerank + 权限过滤。
- `answer`：上下文组装、引用定位、拒答、流式输出。
- `admin`：文档管理、权限、反馈、统计。
- `eval`：100 条评测集跑分、badcase 分类、优化前后对比。
- `deploy`：Docker Compose 一键起。

**验收（M2，01/10）**

- [ ] recall@5 ≥ 85%（以你的评测集为准）
- [ ] faithfulness ≥ 0.85，引用准确率 ≥ 90%
- [ ] 权限用例 0 越权；引用不泄露无权限文档
- [ ] P95 首 token < 2s（非 Agent 问答）
- [ ] 100 条评测集有基线 vs 优化后对比
- [ ] 3 分钟 demo 视频 + README 架构图

**资源**：pgvector 文档、Elasticsearch BM25 文档、bge-m3/bge-reranker 模型卡、RAGAS 文档、Langfuse 文档、Anthropic Contextual Retrieval 文章。

## 5. 学习顺序的原则（为什么这么排）

| 顺序 | 理由 |
|---|---|
| 先 LLM API，再 RAG/Agent | 不会调模型，后面都是空中楼阁 |
| 先手写 tool loop，再用框架 | 面试问原理时，框架救不了你 |
| 先 RAG，再 Agent | RAG 训练检索、上下文、评估；Agent 需要这些地基 |
| 先单 Agent，再多 Agent | 单 Agent 都跑不稳，多 Agent 只会放大问题 |
| 先评测，再优化 | 没有基线，所有优化都是玄学 |
| 先能演示，再完美 | 作品集要的是「能讲清楚」，不是「代码优雅」 |
| 求职与学习重叠 | 面试反馈是最好的学习信号，不要等「学完」 |

## 6. 资源使用原则

1. **官方文档优先**：Spring AI、MCP（2026-07-28）、LangGraph、pgvector、Next.js 的官方文档 > 任何二手教程。
2. **一门课原则**：同一主题最多一门课；没跑完代码不开下一门。
3. **带着问题读**：先写下 3 个问题，再去文档/源码里找答案。
4. **每读必写**：读完一节，写 3 行笔记 + 1 张卡片，否则等于没读。
5. **版本意识**：记录你用的版本；教程过期是常态，以 Release Notes 为准。**MCP 尤其注意：2025 年的 session/SSE 教程已过时。**
6. **AI 编程工具是杠杆**：Claude Code / Codex 从第一周用，但必须读 diff、跑测试、留证据；别把「AI 写的」当「我会了」。
7. **资源清单**：见 `08-资源清单.md`，按优先级和时长选用，不要全看。
