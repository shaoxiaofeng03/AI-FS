## 1. 20K 面试到底在评分什么

面试官通常按 5 个维度打分（不同公司权重不同）：

| 维度 | 权重（估） | 看什么 | 你的策略 |
|---|---|---|---|
| 技术基础 | 25% | LLM/RAG/Agent/工程基础是否扎实 | 题库 + 手写核心机制 |
| 项目深度 | 35% | 是不是真做过、能不能讲清取舍与数字 | Atlas 深挖 + 决策日志 |
| 工程能力 | 20% | 稳定性、性能、成本、安全、排障 | Java 优势 + 生产化报告 |
| 潜力/学习 | 10% | 新东西能不能快速上手 | 转行故事 + 博客/开源 |
| 沟通/匹配 | 10% | 表达、协作、动机、稳定性 | 模拟面试 + 反问 |

**20K 与 15K 的分水岭**：不是「会不会用」，而是「**能不能对结果负责**」。证据就是：指标、故障、取舍、成本、**上线**。

> **2026-11 校准**：样本里 20K 是 3–5 年段的**中低位**（15–25K 区间常见），不是高薪；25–35K 才要求「带过上线的 Agent / 平台」。所以：目标定 20K，谈判开 22–25K，先用一个真上线项目把自己从「15–18K 的 demo 选手」拉到「20K 的交付者」。

## 4. 简历改造

### 4.1 定位

不要写「Java 后端转 AI」，要写「**Java + AI 应用/Agent 工程师**」。标题示例：

> Java 后端 | AI 应用/Agent 开发 | RAG · Agent · Spring AI · 全栈交付

### 4.2 结构（1 页）

1. 基本信息：姓名/电话/邮箱/GitHub/博客/城市。
2. 个人简介 3 行：年限 + 方向 + 最强证据（数字）。
3. 技能：Java/Spring、AI 框架、RAG、Agent、数据、前端、工程化。
4. 项目：Atlas 放第一，3–4 条 bullet；工作项目 2–3 条与 AI/高并发相关。
5. 工作经历：公司/职位/时间/职责/量化成果。
6. 教育/证书/开源/博客。

### 4.3 Before / After

**Before（常见写法）**

> 负责公司知识库项目，使用 LangChain 和向量数据库，实现了问答功能。

**After**

> 主导企业知识库 RAG 全链路（Java 21 / Spring AI / pgvector / Next.js）：设计解析-切分-混合检索-rerank-引用流水线，构建 120 条评测集，recall@5 从 0.71 提升至 0.88，faithfulness 0.91，P95 首 token 1.4s。

### 4.4 量化公式

```
动作（主导/设计/实现/优化）
+ 技术（框架/模型/存储）
+ 规模（文档数/用户数/QPS/并发）
+ 结果（准确率/延迟/成本/稳定性）
+ 业务价值（效率/体验/风险）
```

没有业务数据就用技术指标；没有技术指标就写规模与复杂度；**一个数字都没有的项目，不如不写**。

### 4.5 关键词（过筛用）

RAG、Agent、Function Calling、MCP（2026-07-28）、LangGraph、LangGraph4j、Spring AI 2.x、LangChain4j、Prompt Engineering、上下文工程、Session Memory、Embedding、Rerank、pgvector、Milvus、向量检索、混合检索、多租户、SSE、流式、可观测、Langfuse、评估、RAGAS、成本优化、高并发、Spring Boot、Java 21、虚拟线程、Redis、Docker、K8s（了解）、Next.js、AI SDK、Claude Code。

| A · AI 应用 | RAG + Agent + 全栈 | AI 应用开发、Agent 开发 |

## 5. 项目讲述

### 5.1 3 分钟版（面试开场/HR 面）

```
背景（30s）：企业文档散落、支持工程师找答案慢、跨系统操作多。
问题（30s）：现有搜索找不到、答不准、不敢信；操作要切 5 个系统。
方案（60s）：Atlas = RAG 知识库 + Agent 工作台；Java 后端 + Next.js 前端；
           多租户、权限、引用、工具、审批、评测、成本治理。
结果（30s）：recall@5 0.88、faithfulness 0.91、任务成功率 84%、
           成本 -61%、50 并发 P95 2.1s。
取舍（30s）：为什么 pgvector/状态图/MCP；多 Agent 只用在部分场景。
```

### 5.2 10 分钟版（技术面）

在 3 分钟版基础上加：

- 架构图逐层讲。
- 数据流：文档 → 解析 → 切分 → 索引；问题 → 检索 → rerank → 生成 → 引用。
- 评测：数据集、指标、baseline vs 优化、badcase。
- 一个故障案例：怎么发现、怎么定位、怎么修、怎么防。
- 一个成本优化案例：做了什么、收益多少、代价是什么。

### 5.3 30 分钟版（终面/主管面）

每个模块准备「三层」：

1. **怎么做**：具体实现、参数、代码结构。
2. **为什么**：备选、判据、数据。
3. **代价/替代**：有什么坑、什么情况下换方案、如果重做怎么改。

### 5.4 5 层追问演练

让 AI 或朋友连续追问，直到你答不出：

1. 你的 recall@5 怎么算的？
2. 评测集怎么构造？会不会过拟合？
3. 哪个优化贡献最大？怎么证明？
4. 线上分布和评测集不一致怎么办？
5. 预算减半你砍什么？

**规则**：每层回答不超过 90 秒；答不出就说「这块我没深入，我的理解是……回去我会补」，不要编。

**答题骨架示例（第 3 题）**

> 上下文窗口是模型一次能看的 token 上限。超了有四类做法：截断（快但丢信息）、摘要（省 token 但可能丢细节）、RAG（只取相关片段，最常用）、分层上下文（system/记忆/检索/历史分开预算）。我的项目用分层 + 摘要 + 检索，并记录每层 token 占比；如果超预算，先压缩历史，再减少检索 top-k，最后才换长上下文模型，因为长上下文成本和延迟都更高。

**答题骨架示例（第 14 题）**

> 先按链路分段定位：① 看检索结果里有没有正确文档（recall）——没有就是解析/切分/检索问题；② 有正确文档但答案错——看上下文是否被截断、噪声是否太多、prompt 是否约束不足；③ 上下文对但模型编——看 faithfulness 和引用是否匹配。我会用固定评测集 + trace 回放，逐段打分，再针对性修。比如我们一次 badcase 是表格被切碎，改成按表格整块切分后 recall@5 从 0.72 到 0.81。

**答题骨架示例（第 11 题）**

> Function Calling 是模型输出「要调用哪个函数、参数是什么」的协议；MCP 是更上层的**工具接入标准**，定义了 server 如何暴露 tools/resources/prompts，client 如何发现和调用，传输可以用 stdio 或 Streamable HTTP。区别：Function Calling 解决「模型怎么表达调用意图」，MCP 解决「工具怎么标准化接入、复用、权限和生态」。**2026-07-28 规范把 MCP 做成无状态协议**：去掉 session 和 initialize 握手，新增 `server/discover`，用 MRTR（`input_required`）承载多轮/人工确认，tasks 转扩展。我的项目里，内部 Java 服务用 MCP server 暴露，Agent 通过 MCP client 发现工具；同时单次推理仍用 Function Calling 表达调用。MCP 的风险是第三方 server 不可信，所以做了白名单、版本锁定和权限分级。

**答题骨架示例（第 9 题）**

> 一次请求建一个 trace，span 包括：检索（query、top-k、耗时、命中文档）、rerank、模型调用（provider/model、prompt/completion tokens、首 token/总耗时、成本）、工具调用（工具名、参数脱敏、结果状态、耗时）、审批（等待/结果）。再挂业务维度：tenant、user、conversation、run。这样既能看单次回放，也能聚合 P95、错误率、成本。工具用 OTel + Langfuse；关键是**每次 run 都能回放**，否则线上问题只能猜。

## 7. 系统设计（5 题）

### 7.1 通用框架（1 小时）

1. **澄清**（5min）：用户、场景、规模、SLA、约束、不做什么。
2. **估算**（5min）：DAU/QPS、文档量、token/请求、存储、成本。
3. **高层架构**（10min）：前端、API、核心服务、存储、模型、异步。
4. **数据模型**（10min）：核心表/索引/权限。
5. **核心流程**（10min）：写路径、读路径、异常路径。
6. **关键取舍**（10min）：向量库、同步/异步、缓存、多租户、评测。
7. **失败与降级**（5min）：模型挂、检索慢、超时、限流。
8. **评测与运维**（5min）：指标、trace、告警、灰度。
9. **演进**（5min）：下一步。

### 7.2 设计一：企业知识库问答

关键点：多租户、文档 ACL、解析/切分、混合检索、rerank、引用、增量索引、评测、拒答、成本。

**追问**：100 万文档怎么索引？权限怎么过滤？文档更新怎么保证一致性？答案错了怎么定位？

### 7.3 设计二：Agent 平台

关键点：工具注册、状态图、checkpoint、HITL、记忆、沙箱、trace、预算、多 Agent、评测。

**追问**：如何防止工具滥用？如何恢复中断？如何评测？多 Agent 怎么编排？

### 7.4 设计三：AI 网关

关键点：统一接口、路由、降级、灰度、配额、计费、缓存、可观测、密钥管理。

**追问**：如何做到多模型无缝切换？如何按租户限流？如何灰度 prompt？如何算成本？

### 7.5 设计四：智能客服

关键点：意图识别、知识库、工单工具、人工转接、情绪识别、质检、多轮、合规。

**追问**：如何避免答错？如何转人工？如何评估满意度？

### 7.6 设计五：文档审核/抽取

关键点：多模态解析、结构化输出、规则校验、人工复核、版本、审计、准确率。

**追问**：如何处理扫描件？如何保证字段准确？如何做人工兜底？

## 8. 手撕 / 编码

### 8.1 刷题计划

- 总量：60–80 题（Hot 100 里选），不追求 300 题。
- 节奏：W3 起每周 2–3 题；W18 起每天 1 题保持手感。
- 重点：数组/字符串/哈希/双指针/滑动窗口/二叉树/DFS/BFS/堆/二分/动态规划（简单-中等）。
- 语言：Java 为主，Python 为辅（看岗位）。
- 方法：先自己想 15 分钟，再看题解，第二天重写。

### 8.2 AI 特色实现题（面试常考）

| 题目 | 考什么 | 要点 |
|---|---|---|
| 实现 tool calling 循环 | 协议、状态、终止 | tool_calls 解析、结果追加、最大步数 |
| 实现 ReAct | 推理循环 | thought/action/observation、解析、异常 |
| 实现令牌桶限流 | 并发 | 时间戳/桶容量、线程安全 |
| 实现 LRU | 数据结构 | HashMap + 双向链表 |
| 实现 SSE 接口 | Web | `text/event-stream`、flush、心跳、断连 |
| 实现 BM25 | 检索 | tf/idf、长度归一化、倒排 |
| 实现 RRF | 融合 | 排名倒数求和、k 值 |
| 实现余弦相似度/TopK | 向量 | 归一化、堆 |
| 实现重试+退避+熔断 | 可靠性 | 指数退避、jitter、半开 |
| 实现简易分词 | 中文 | 词典/最大匹配（说清局限） |
| 实现语义缓存 | 成本 | 相似度阈值、失效、白名单 |
| 实现对话摘要 | 上下文 | 触发条件、保真、token 预算 |

### 8.3 编码注意

- 先讲思路，再写代码；边写边说边界。
- 空输入、超长、并发、异常、幂等。
- Java 用 `ConcurrentHashMap`/`AtomicInteger`/`CompletableFuture` 要能解释。
- 不会优化就说「先正确，再优化」，不要沉默。

## 12. 薪资谈判

### 12.1 先算清楚

| 项 | 你的情况 |
|---|---|
| 当前月薪 | ___ |
| 目标月薪 | 20K |
| 最低接受 | ___（覆盖房贷/生活/风险） |
| 其他 offer | ___ |
| BATNA（没有 offer 怎么办） | 继续投/外包/远程/延后 |

> **校准**：2026-11 样本里 20K 是 3–5 年段的**中低位**，所以别把 20K 当「高薪目标」而放松准备；它只是「上岸线」。真正决定你谈 20K 还是 25K 的，是「有没有上线 + 评测 + 工程化」三件套。

### 12.2 报价策略

- 目标 20K，**开口 22–25K**（给谈判空间），但要有依据（项目/市场/当前薪资）。
- 先问区间：「这个岗位的薪资带宽是多少？」再报期望。
- 不要先说「都可以」；不要说谎报当前薪资（背调会查）。
- 总包思维：月薪 × 12/13/15 + 签字费 + 期权 + 补贴 + 远程。
- 有竞争 offer 时，如实说「有另一个流程在走」，不要编。

### 12.3 话术

**被问期望薪资**

> 我目前的期望是 22–25K，主要依据是：我有 3 年 Java 后端经验，独立完成了企业级 RAG + Agent 项目，有评测、成本、高并发的数字；也了解市场上同类岗位的区间。具体也想结合岗位职责和团队来看。

**对方压价**

> 理解预算限制。如果月薪空间有限，能否在签字费/职级/入职时间/远程弹性上调整？另外我想确认一下，这个岗位的成长路径和调薪周期是怎样的。

**拿到 offer 后**

> 感谢认可。我对团队和方向很感兴趣，想确认几个细节：薪资结构、绩效比例、试用期、社保公积金基数、年假、加班情况。如果都合适，我可以在 X 天内确认。

## 13. 转行动机与常见质疑

### 13.1 「为什么从 Java 转 AI？」

**结构**：能力迁移 + 项目证据 + 长期判断 + 匹配岗位。

> 我不是逃离 Java，而是把 Java 的工程能力迁移到 AI 应用。过去一年我做了 Atlas 项目，从 RAG 到 Agent 到生产化，发现企业真正缺的不是会调 API 的人，而是能把 AI 做得稳定、可观测、算得清成本的人，这正好是我的优势。我也在现公司推动了 XX 小需求落地。长期我想做企业级 AI 应用/Agent 平台，所以选择这个方向。

### 13.2 「你没有 AI 工作经验」

> 是的，我没有 AI 岗位的正式 title，但我有可验证的项目：Atlas 的代码、评测报告、压测/成本/安全报告、6 篇博客都在 GitHub 上；我也在现公司落地了 XX。面试可以随便挑一个模块深挖。

### 13.3 「为什么值 20K？」

> 我能独立负责一个 AI 功能/模块从设计到上线：RAG/Agent 全链路、评测、成本、安全、前端交付都能做；我也能用 Java 后端的工程能力降低上线风险。我的项目已经部署，有可访问的 demo、真实使用数据（哪怕 10 个用户）、评测报告和压测/成本数字。20K 对应的是「能独立交付、对结果负责」的档位，我拿这些证据来证明这一点。

## 17. 心态

- **被拒是常态**：120 投 → 15 面 → 3 offer 是正常漏斗；被拒不代表你不行。
- **不要比较**：别人 3 个月拿 offer 可能基础/运气不同；你只和昨天的自己比。
- **面试是双向**：你也在选公司；问清楚加班、技术栈、成长。
- **保持节奏**：面试期也要每天 commit/卡片，手感会掉。
- **拿到 offer 不是终点**：入职前 30 天决定试用期；长期靠持续学习。

> 最后一句话：**面试考的不是你知道多少，而是你能不能在 45 分钟内证明「把事交给你，我放心」。**
