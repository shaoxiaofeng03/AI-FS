## 0. 执行摘要（5 条）

1. **岗位已成形，要求高度趋同**：Python 或 Java 任一后端语言 + RAG + Tool Calling + 向量库 + Docker/K8s + **MCP** + **Claude Code/Cursor 实操**。MCP 被多家分析称为 2026 年增速最快的单一技能（B 级）。
2. **20K 档真实存在但层级偏低**：2026-11-05 猎聘「Agent 开发工程师」首屏约 40 条中，3–5 年段出现 15–25K、20–30K·17 薪、25–40K 多档；20K 落在**中低位**，典型是外包/中型软件/传统行业数字化，而非大厂应用算法岗（B 级，见 §1.2）。
3. **Java 侧栈可用但慢半拍**：Spring AI 已到 **2.0.2（2026-10-23）/2.1.0-RC1**；LangChain4j 到 **1.23.0（2026-10-28）**；LangGraph4j 到 **v1.8.8**；而 Spring AI Alibaba 可查最新为 **1.1.2.0（2026-02-03，对齐 Spring AI 1.1.2）**，社区有「停更/转向 AgentScope」讨论（见 §2.2）。
4. **MCP 在 2026-07-28 做了史上最大改动：去会话、去 initialize 握手、改 `server/discover`、引入 MRTR**，2025 年教程写法已过时，答错明显扣分（A 级）。
5. **AI 编程工具已进 JD 正文**：某北京 3–5 年 Agent 岗（15–25K）明确要求「Claude Code、Codex 重度使用经验」（B 级）——这是「在职 + 时间少」者最強的杠杆点。

### 2.1 Java 侧：Spring AI（A 级）

| 版本 | 日期 | 关键内容 | 来源 |
|---|---|---|---|
| 2.0.0-M2 | 2026-01-23 | 2.0 线里程碑 | [spring.io](https://spring.io/blog/2026/01/23/spring-ai-2-0-0-M2-available-now/) |
| **2.0.0 GA** | **2026-06-12** | 2.0 正式版 | [spring.io](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now) |
| 2.0.1 | 2026-08-21 | 维护更新 | [spring.io](https://spring.io/blog/2026/08/21/spring-ai-2-0-1-available-now) |
| **2.0.2 + 2.1.0-RC1** | **2026-10-23** | 2.0.2 为 2.0.x 维护版；2.1.0-RC1 引入 Session Memory、工具调用确认、Message Parts、预计算向量检索 | [spring.io](https://spring.io/blog/2026/10/23/spring-ai-2-1-0-RC1-available-now) |

**2.1 新增能力（面试与选型都要用到的四个点，B 级转述 + 官方文档链接）**

1. **Session Memory**：把会话历史存成 **append-only 事件日志**，按需构建「活动视图」；`TurnCountTrigger` 触发压缩、`WindowCompactionStrategy` 保留最近 N 个**完整回合**（不会在工具调用与结果之间切断）；`InMemorySessionRepository` / `JdbcSessionRepository`（PostgreSQL/MySQL/MariaDB/H2）。旧的 `ChatMemory`、`MessageChatMemoryAdvisor` 已标记弃用、计划 3.0 移除。官方文档：[Session Memory](https://docs.spring.io/spring-ai/reference/2.1/api/session.html)。**这是「上下文工程」在 Java 生态的落地答案**。
2. **工具调用确认（human-in-the-loop）**：`@Tool(requiresConfirmation = true)`，模型提出调用后**先暂停**，应用收集 `ToolCallDecision`，再用 `ToolCallingManager.executeToolCalls(...)` 继续。[官方文档](https://docs.spring.io/spring-ai/reference/2.1/api/tools/tool-call-confirmation.html)。注意：**确认机制不等于授权**，服务端仍须做鉴权/归属校验/幂等/重放防护。
3. **Message Parts**：把「文本 / 工具调用 / 推理内容 / 厂商私有块」作为有序结构保留，扩展到 OpenAI、Anthropic、Google GenAI、Bedrock Converse、Ollama、Mistral、DeepSeek 等；OpenAI 兼容接口新增 `spring.ai.openai.chat.replay-reasoning-content` 开关。
4. **预计算向量检索**：可直接用外部算好的 `float[]` 做 `similaritySearch`，覆盖 pgvector / Qdrant / Redis / Elasticsearch（OpenSearch 扩展支持）；向量维度与向量空间必须匹配，不支持时快速抛 `UnsupportedOperationException`。

**选型建议（推测 + 依据）**：学习与作品集用 **2.0.x 稳定线**（2.0.2）；简历上写「了解 2.1 的 Session Memory / 工具确认 / Message Parts」即可，不必在 RC 上做正片项目。Spring Boot 版本兼容务必按 [Upgrade Notes](https://docs.spring.io/spring-ai/reference/2.1/upgrade-notes.html) 核对。

**存疑点 1（版本对齐）**：截至 2026-11-05，可核实的最新 Spring AI Alibaba 版本仍为 **1.1.2.0（基于 Spring AI 1.1.2）**，而 Spring AI 主线已到 2.0.2 / 2.1-RC1；**未核实到**「已发布对齐 2.0 版本」的官方公告。做作品集建议**二选一**：只用 Spring AI 2.0.x，或只用 SAA 1.1.2.0，**不要混用**。

**存疑点 2（社区「停更」传闻）**：中文社区有标题为「我分析了 Spring AI Alibaba 的停更背后」的转载（[51cto](https://blog.51cto.com/u_16213612/15001556)），正文未抓取，**真实性未核实**；另有 `agentscope-java` issue 提议把 `spring-ai-alibaba-graph-core` 迁入 AgentScope 作为可选工作流扩展（[#3827](https://github.com/agentscope-ai/agentscope-java/issues/3827)），及官方博文《Spring AI Alibaba 与 AgentScope 的定位与区别》。**替代判断**：阿里系在做「AgentScope（模型/多智能体）+ SAA（Java 落地）」分工，短期不会废弃；学习**80% 精力放 Spring AI 本体 + 通用 Agent 概念**，SAA 专有能力作加分项。

### 2.4 MCP 生态：2026 年最大变化（A 级，必须核对）

**MCP 规范 2026-07-28** 相对 2025-11-25 是「史上最大更新」，核心是**把 MCP 做成无状态协议**（[官方 Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)）：

| 变化 | 内容 | 对面试/工程的影响 |
|---|---|---|
| **移除协议级会话** | 删除 `Mcp-Session-Id`；`tools/list` 等列表端点不再随连接变化；跨调用状态改用**服务端签发的 handle** 作为普通工具参数（SEP-2567） | 「MCP 靠 session 维持上下文」的旧答法作废 |
| **无状态化** | 删除 `initialize` / `notifications/initialized` 握手；每个请求在 `_meta` 里带 `protocolVersion` / `clientCapabilities`；版本不匹配返回 `UnsupportedProtocolVersionError`（SEP-2575） | 客户端实现大幅简化，网关/负载均衡友好 |
| **新增 `server/discover`** | 服务端**必须**实现，用于声明支持的协议版本、能力与身份 | 企业级 MCP 注册/发现的基础 |
| **`subscriptions/listen`** | 取代 HTTP GET 端点与 `resources/subscribe`/`unsubscribe`，单一长连 POST 响应流承载变更通知 | 流式与通知模型统一 |
| **MRTR（多轮请求）** | 取代服务端主动发起请求；服务端返回 `InputRequiredResult`（`resultType: "input_required"`）携带 `inputRequests`，客户端重发原请求带 `inputResponses`（SEP-2322） | **这正是「工具调用确认 / 人工审批」的协议级支撑**，与 Spring AI 的 tool-call confirmation 呼应 |
| **tasks 变扩展** | 移出核心，改为 `io.modelcontextprotocol/tasks` 扩展，`tasks/result` 阻塞改为 `tasks/get` 轮询 + `tasks/update`（SEP-2663） | 长任务（DeepResearch 类）实现方式变更 |
| **移除 SSE 续传** | 删除 `Last-Event-ID` 与事件 ID，断流即请求丢失，客户端须用新 request id 重发 | 可靠性设计责任转移到客户端 |
| **移除 `ping` / `logging/setLevel` / roots 变更通知** | 日志级别改为在 `_meta` 里按请求传 `logLevel` | — |

辅助佐证（B 级）：[Gigazine 报道](https://gigazine.net/gsc_news/en/20260729-model-context-protocol-2026-07-28)、上一版规范 [2025-11-25 Changelog](https://modelcontextprotocol.io/specification/2025-11-25/changelog)。

> **学习建议（重要）**：2025 年绝大多数中文 MCP 教程基于「SSE + initialize + session」，**已过时**。学习时以 `modelcontextprotocol.io` 当前版本为唯一事实源，并注意 Java 侧框架（Spring AI、LangChain4j）的 MCP 客户端/服务端实现是否已跟进 2026-07-28 规范——**这一点本文未逐一核实到框架层支持状态**（见 §8 存疑点）。

**A. Agent 原理（必答）**

| # | 问题 | 一句话应答骨架 |

| 1 | LLM 和 Agent 的区别？ | LLM 是无状态条件概率函数；Agent = LLM + 工具 + 记忆 + 规划，在循环中自主完成目标。要能展开「只会说不会做/没记忆/知识截止/不会规划」四大天花板 |

### 3.3 20K 候选人的区分点（推测，基于 JD 与面试结构反推）

1. **有「上线」而不是「跑通」**：能说出日调用量、P95 延迟、单次成本、错误率。这一条把 80% 转岗者刷掉。
2. **有评测**：能拿出 50 条标注集 + RAGAS/Langfuse 截图 + 「改了什么指标涨了多少」。
3. **有工程收敛**：知道什么场景**不该**用 Agent（用 Workflow 更稳更省），能报出 token 倍数。
4. **AI 编程工具有证据**：GitHub commit 历史、Claude Code 用量、能讲「我怎么用 coding agent 在 2 周做完一个全栈 demo」。
5. **Java 底座的迁移故事**：把「Spring 事务/幂等/限流/MQ 重试」映射到 Agent 可靠性设计——这是纯 Python 转岗者讲不出的差异化。

## 6. 结论：给 Java 后端的 10 条建议

1. **不要转 Python 主线**。用「Java（Spring AI / LangChain4j）交付 + Python 能读能改」打差异化；Java+AI 双栈在传统行业与央企岗位上是稀缺组合。
2. **作品集只要 1 个，但必须上线**。一个「Spring Boot + Spring AI + pgvector + MCP 工具 + Next.js 前端 + Langfuse 观测」的完整系统，胜过 5 个 demo。
3. **把「评测」当作 20K → 25K 的杠杆**。50 条标注集 + RAGAS 分数 + Langfuse trace，是面试中最容易被记住的差异化。
4. **MCP 必须学 2026-07-28 新规范**。旧教程的 session/SSE 写法已过时；能说出「无状态化 + MRTR + server/discover」直接体现信息新鲜度。
5. **Claude Code 从第一周就用，并留下证据**。JD 已把「重度使用经验」写成硬要求；commit 历史、CLAUDE.md、Skill 文件就是证据。
6. **前端只学到「能交付 demo」为止**。Next.js + AI SDK 6 + shadcn/ui，2–3 周，不要碰 React 原理与状态管理深水区。
7. **上下文工程优先于 Prompt 技巧**。学 Spring AI 2.1 的 Session Memory、回合压缩、渐进式 Skills 披露——这是 2026 年面试的「新八股」。
8. **把 Java 可靠性经验显式翻译成 Agent 语言**：幂等↔重试安全、限流↔token 预算、熔断↔工具降级、事务↔状态一致性、MQ 死信↔失败任务重放。
9. **接受「外包/中型厂/传统行业」作为 20K 的第一站**，1–2 年后带着「已上线 Agent 系统」再跳，薪资与岗位质量会显著改善。
10. **不要碰训练侧**（SFT/RLHF/千卡）与算法岗，22 周投入产出比极低；应用岗 20K 不考这些。

### 20K 最短路径判断（推测，但基于上述事实）

| 阶段 | 时间 | 目标 | 判定标准 |
|---|---|---|---|
| 打地基 | 2026-11 → 2027-01（约 10 周） | Spring AI + RAG + 前端 demo 跑通 | 能独立做出「上传文档→检索问答→流式前端」并部署 |
| 做作品 | 2027-01 → 2027-02（约 6 周） | 1 个上线级 Agent 系统 + 评测 + trace | 有 URL、有 Langfuse 截图、有 50 条标注集、有成本数字 |
| 面试准备 | 2027-02（约 3 周） | §3 的 35 题 + 项目故事 3 版（3 分钟/10 分钟/30 分钟） | 任意一题能讲 5 分钟且经得起追问 |
| 投放 | 2027-03 → 04（约 5 周） | 年前试探 5 家 + 金三银四集中投 30–50 家 | 拿到 ≥3 个 20K+ offer 谈判 |

**核心判断**：22 周足够达到 20K 档，但**前提是「1 个真上线项目 + 评测证据 + Claude Code 效率故事」三件套齐全**；缺任何一件，20K 会变成 15–18K 的外包岗。
